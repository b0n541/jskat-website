Ihre Idee am Tisch

Eine eigene Skat-KI entwickeln

JSkat ist ein offenes Spielfeld für neue Strategien. Bauen Sie das Projekt, lernen Sie die vorhandenen Spieler kennen und bringen Sie Ihren eigenen Ansatz in eine echte Skatpartie.

Loslegen

Vom Repository zur ersten Änderung

Sie brauchen Git und mindestens JDK 21. Der Gradle Wrapper liegt im Repository, deshalb müssen Sie Gradle nicht separat installieren. Eine Java-IDE ist hilfreich, aber für den ersten Build nicht erforderlich.

01

Repository forken und klonen

Forken Sie JSkat auf GitHub und klonen Sie Ihren Fork. So können Sie Änderungen unabhängig vorbereiten.

git clone https://github.com/IHR-NAME/jskat.git cd jskat
02

Projekt bauen

Der vollständige Build prüft das Projekt und erzeugt anschließend eine ausführbare JAR-Datei.

./gradlew clean build ./gradlew fatjar
03

Orientierung im Code

Die Spiellogik und KI-Bausteine liegen in jskat-base. Die JavaFX-Oberfläche befindet sich in jskat-gui, der Anwendungsstart in app.

04

Einen Spieler als Ausgangspunkt wählen

Der kleinste vollständige Ausgangspunkt ist AIPlayerRND im Package org.jskat.ai.rnd. Kopieren Sie seine Struktur in ein eigenes Package, zum Beispiel org.jskat.ai.myplayer, und lassen Sie Ihre Klasse weiterhin von AbstractAIPlayer erben. Die abstrakte Basisklasse stellt den gemeinsamen Spielzustand bereit und markiert Ihre Implementierung automatisch als KI-Spieler. Ihre Klasse braucht außerdem einen öffentlichen Konstruktor ohne Parameter, weil JSkat normale KI-Spieler per Reflection erzeugt.

05

Den neuen KI-Spieler implementieren und registrieren

Eine KI wird während einer Partie mehrfach nach Entscheidungen gefragt. Die geerbte Variable knowledge enthält dabei unter anderem die eigenen Karten, Sitzposition, bisherigen Gebote, den aktuellen Stich, den Alleinspieler und den Spielvertrag.

  1. Lebenszyklus vorbereiten Nutzen Sie prepareForNewGame(), um den Zustand vor jeder neuen Partie zurückzusetzen. startGame() wird aufgerufen, sobald Alleinspieler und Spielvertrag feststehen.
  2. Reizstrategie festlegen bidMore(int nextBidValue) gibt das nächste Gebot oder 0 zum Passen zurück. holdBid(int currBidValue) entscheidet, ob ein genanntes Gebot gehalten wird.
  3. Skat und Spielansage behandeln pickUpSkat() entscheidet über die Aufnahme. getCardsToDiscard() muss danach genau zwei Karten zurückgeben. Mit announceGame() erzeugen Sie den gewünschten GameContract.
  4. Eine erlaubte Karte ausspielen Rufen Sie zuerst getPlayableCards(knowledge.getTrickCards()) auf. Wählen Sie ausschließlich aus dieser Liste, damit Bedienpflicht und Spielregeln eingehalten werden.
  5. Sonderfälle und Abschluss ergänzen Implementieren Sie playGrandHand(), callContra() und callRe(). In finalizeGame() können Sie Statistiken aktualisieren oder Lernschritte nach Abschluss einer Partie ausführen.

Der Kern einer legalen Kartenauswahl kann so aussehen:

public final class MyAIPlayer extends AbstractAIPlayer { public MyAIPlayer() { // Wird von JSkat per Reflection aufgerufen. } @Override public Card playCard() { CardList playable = getPlayableCards(knowledge.getTrickCards()); return chooseCard(playable); } // Die übrigen abstrakten Entscheidungen ebenfalls // wie in AIPlayerRND implementieren. }
Damit die neue KI im Startdialog erscheint

Ergänzen Sie den vollständig qualifizierten Klassennamen in JSkatPlayerResolver.getAllAIPlayerImplementations(). Fügen Sie anschließend in SkatSeriesStartDialog.PlayerTypeCell eine lesbare Beschriftung hinzu. Den Textschlüssel tragen Sie in jskat_strings_de.properties und jskat_strings_en.properties ein.

Legen Sie Tests im passenden Package unter jskat-base/src/test/java/org/jskat/ai ab. Beginnen Sie mit kleinen, deterministischen Fällen für Reizen oder Kartenauswahl und führen Sie sie mit ./gradlew :jskat-base:test aus.

06

Beitrag einreichen

Erstellen Sie Ihren Feature-Branch vom Branch develop. Öffnen Sie anschließend einen Pull Request zurück nach develop und beschreiben Sie Idee und Verhalten Ihrer Änderung.

Guter Einstieg

Sie müssen nicht mit einer kompletten KI beginnen

Auch kleinere Beiträge bringen das Projekt weiter: ein reproduzierbarer Fehlerbericht, ein zusätzlicher Testfall, verständlichere Dokumentation oder eine Verbesserung der JavaFX-Oberfläche. Offene Issues zeigen, wo gerade Hilfe gebraucht wird.

Stellen Sie eine Frage oder wählen Sie ein überschaubares Issue aus.
