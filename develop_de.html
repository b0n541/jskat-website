Für Entwickler

Eine eigene Skat-KI entwickeln

JSkat enthält mehrere Computerspieler und lässt sich um eigene ergänzen. Diese Anleitung zeigt dir, wie du das Projekt baust, den passenden Code findest und einen neuen Spieler ins Spiel einbindest.

Projekt einrichten

JSkat bauen und den Code kennenlernen

Du brauchst Git und mindestens JDK 21. Der Gradle Wrapper liegt im Repository, deshalb musst du Gradle nicht separat installieren. Eine Java-IDE ist hilfreich, für den ersten Build reicht aber auch ein Terminal.

01

Repository forken und klonen

Forke JSkat auf GitHub und klone deinen Fork. Dort kannst du deine Änderungen vorbereiten und veröffentlichen.

git clone https://github.com/IHR-NAME/jskat.git cd jskat
02

Projekt bauen

Der vollständige Build prüft das Projekt und erzeugt anschließend eine ausführbare JAR-Datei.

./gradlew clean build ./gradlew fatjar
03

Die wichtigsten Module finden

Die Spiellogik und KI-Bausteine liegen in jskat-base. Die JavaFX-Oberfläche befindet sich in jskat-gui, der Anwendungsstart in app.

04

Mit einem vorhandenen Spieler beginnen

Der kleinste vollständige Ausgangspunkt ist AIPlayerRND im Package org.jskat.ai.rnd. Kopiere seine Struktur in ein eigenes Package, zum Beispiel org.jskat.ai.myplayer, und lass deine Klasse weiterhin von AbstractAIPlayer erben. Die abstrakte Basisklasse stellt den gemeinsamen Spielzustand bereit und markiert deine Implementierung automatisch als KI-Spieler. Deine Klasse braucht außerdem einen öffentlichen Konstruktor ohne Parameter, weil JSkat normale KI-Spieler per Reflection erzeugt.

05

Den neuen KI-Spieler implementieren und registrieren

Eine KI wird während einer Partie mehrfach nach Entscheidungen gefragt. Die geerbte Variable knowledge enthält dabei unter anderem die eigenen Karten, Sitzposition, bisherigen Gebote, den aktuellen Stich, den Alleinspieler und den Spielvertrag.

  1. Lebenszyklus vorbereiten Nutze prepareForNewGame(), um den Zustand vor jeder neuen Partie zurückzusetzen. startGame() wird aufgerufen, sobald Alleinspieler und Spielvertrag feststehen.
  2. Reizstrategie festlegen bidMore(int nextBidValue) gibt das nächste Gebot oder 0 zum Passen zurück. holdBid(int currBidValue) entscheidet, ob ein genanntes Gebot gehalten wird.
  3. Skat und Spielansage behandeln pickUpSkat() entscheidet über die Aufnahme. getCardsToDiscard() muss danach genau zwei Karten zurückgeben. Mit announceGame() erzeugst du den gewünschten GameContract.
  4. Eine erlaubte Karte ausspielen Rufe zuerst getPlayableCards(knowledge.getTrickCards()) auf. Wähle ausschließlich aus dieser Liste, damit Bedienpflicht und Spielregeln eingehalten werden.
  5. Sonderfälle und Abschluss ergänzen Implementiere playGrandHand(), callContra() und callRe(). In finalizeGame() kannst du Statistiken aktualisieren oder Lernschritte nach Abschluss einer Partie ausführen.

Der Kern einer legalen Kartenauswahl kann so aussehen:

public final class MyAIPlayer extends AbstractAIPlayer { public MyAIPlayer() { // Wird von JSkat per Reflection aufgerufen. } @Override public Card playCard() { CardList playable = getPlayableCards(knowledge.getTrickCards()); return chooseCard(playable); } // Die übrigen abstrakten Entscheidungen ebenfalls // wie in AIPlayerRND implementieren. }
Damit die neue KI im Startdialog erscheint

Ergänze den vollständig qualifizierten Klassennamen in JSkatPlayerResolver.getAllAIPlayerImplementations(). Füge anschließend in SkatSeriesStartDialog.PlayerTypeCell eine lesbare Beschriftung hinzu. Den Textschlüssel trägst du in jskat_strings_de.properties und jskat_strings_en.properties ein.

Lege Tests im passenden Package unter jskat-base/src/test/java/org/jskat/ai ab. Beginne mit kleinen, deterministischen Fällen für Reizen oder Kartenauswahl und führe sie mit ./gradlew :jskat-base:test aus.

06

Beitrag einreichen

Erstelle deinen Feature-Branch vom Branch develop. Öffne anschließend einen Pull Request zurück nach develop und beschreibe Idee und Verhalten deiner Änderung.

Andere Möglichkeiten mitzuhelfen

Du kannst auch kleiner anfangen

Ein nachvollziehbarer Fehlerbericht, ein zusätzlicher Testfall, verständlichere Dokumentation oder eine Verbesserung der Oberfläche helfen ebenfalls. In den offenen Issues siehst du, woran gerade gearbeitet wird und wo Hilfe gebraucht wird.
